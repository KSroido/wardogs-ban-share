# Roadmap

按优先级排列。欢迎在 Issue 里认领；改动前先开 Issue 对齐范围。

## P0 — 上线后应该尽快补

- [ ] **请求限流 / 配额**
  目前没有频率限制，泄露的 key 在吊销前可以持续写入。计划：按 key + 按 IP 的滑动窗口，写入 60/min、读取 300/min，超出返回 `429` + `Retry-After`。
- [ ] **Worker 集成测试**
  现在只有校验函数和 SDK 的单元测试。计划用 `@cloudflare/vitest-pool-workers` 跑真实的 D1 迁移 + 路由测试。
- [ ] **备份自动化**
  D1 每周导出到 R2，保留 8 周；导出任务不在本仓库里存任何凭据。

## P1 — 安全与治理

- [ ] **key 作用域细分**
  当前只有 `bans:read` / `bans:write`。计划增加 `bans:read:full`（含证据 URL）与 `bans:read:aggregate`（只读举报人数），便于面板和机器人使用低权限 key。
- [ ] **申诉链接字段**
  每条记录增加 `appeal_url`，由上报服自己维护；联盟不代审，但要让被封玩家找得到入口。
- [ ] **证据托管**
  可选上传到 R2（私有 bucket + 签名 URL），避免外链失效。需要配额和滥用防护。
- [ ] **自动过期清理**
  `expired` 记录保留策略：默认永久保留（历史价值），提供按服务器导出/删除。

## P2 — 接入体验

- [ ] **Webhook 推送**
  `ban.created` / `ban.revoked` 事件，成员服可订阅，减少轮询。需要签名（HMAC）和失败重试。
- [ ] **CSV / 批量导入**
  从现有的 `bans.sqlite` / CSV 迁移，带 dry-run 和逐行报告。
- [ ] **管理 UI**
  维护者用的轻量页面：建服、发 key、看审计、紧急撤销。必须走 Cloudflare Access。
- [ ] **SDK 发布**
  - TS：发布到 npm（`@wardogs/banlist`）
  - Python：发布到 PyPI（`wardogs-banlist`）
  - Go：打 tag，让 `go get` 可用
- [ ] **SDK 一致性测试**
  同一组请求/响应 fixture 跑三套 SDK，防止行为漂移。
- [ ] **接入示例**
  - 常见的 RCON / 管理插件接入片段
  - 定时同步 + 本地 SQLite 的完整可运行 demo

## P3 — 生态

- [ ] **联盟治理文档**
  审核标准、误封争议处理、退盟流程、数据保留期限。
- [ ] **统计页**
  公开的匿名汇总（不暴露 SteamID）：每日新增、按 reason 分布、按服分布。
- [ ] **多区域部署**
  当前单 Worker + 单 D1。如果跨区延迟成为问题，再考虑只读副本或边缘缓存。
- [ ] **告警**
  Worker 错误率、D1 写入失败、cron 未执行时通知维护者。

## 明确不做

- **不做自动踢人**：名单是情报，执行策略由各服自己决定。
- **不做公开匿名查询**：SteamID64 属于个人信息，读接口必须持 key。
- **不托管聊天记录/录像原文件**（除非 P1 的 R2 方案落地）。
- **不替成员服做申诉裁决**。

## 版本

- `0.1.0`：当前版本，API `/v1`，三语言 SDK，单 D1，Workers Builds 部署。
